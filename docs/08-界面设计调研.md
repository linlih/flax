# 08 界面设计调研：好看的应用是怎么做的

> 2026-11-04。原型 v0.3（Apple 原生感）用户反馈"还是不是很美观"，于是调研几款公认设计好的应用，找出它们共同的做法，并对照诊断 v0.3。

## 2. 共同做法

1. **好看来自真实内容，不是界面装饰。** Craft 的卡片里是文档的真实文字，Reeder 的列表和正文里有真实图片，Highlights 的缩略图是真实渲染的 PDF 页面。界面本身几乎没有颜色和装饰。
   - 对我们的意义：论文首页本身就是最好的视觉素材（标题、作者、摘要、图表），一定要画得像真的。
2. **导航退后，内容在前。** Linear 把侧边栏"调暗了几档"，原则是"不要争夺你没有赢得的注意力"。Craft 和 Reeder 的侧边栏图标都是灰色线性图标，只有选中项稍微突出。
3. **结构靠间距和对齐，不靠线。** Linear 减少分隔线、降低对比度，"结构应该被感觉到，而不是被看到"。NN/g 也把对齐网格、组内间距小于组间间距列为首要因素。
4. **大标题建立层次。** Reeder 的列表栏顶部是粗体大标题（"Home"），Things 每个列表都有粗大的标题。页面的层次一眼就能看出：大标题、分组、内容。
5. **一套间距、一套字体，处处一致。** NN/g 认为视觉一致性是精致感的主要来源。Linear 标题用 Inter Display、正文用 Inter，没有第三种。
6. **颜色极少且有含义。** Things 只有一种蓝；Linear 改版时专门"降低了界面框架的颜色"。

## 3. 对照诊断 v0.3

| 问题 | 表现 | 违背了哪条 |
|---|---|---|
| 内容是假的 | 缩略图是灰色横条，看起来像线框图，不像产品 | 1 |
| 侧边栏太抢眼 | 每一行的图标都是蓝色，左侧是一整列蓝 | 2、6 |
| 默认选中行太重 | 一整行实心蓝色是全屏最重的元素，但它没有意义（用户还没选任何东西） | 2、6 |
| 构图松散 | "继续阅读"只有 3 本小书靠左，右边大片空白；列表的标题列和标签列相隔很远，眼睛要横跨整屏 | 3 |
| 标题重复 | 工具栏、侧边栏、分区标题三处都写"全部论文" | 4 |
| 列表没有图像 | 纯文字行，很难扫读和辨认 | 1 |

## 4. v0.4 的改法

- **真实的论文缩略图**：按真实论文首页排版（标题、作者、单位、摘要、正文、页码），再整体缩小显示，小字自然变成真实的文字纹理；缩略图上能看到黄色高亮的位置。文献库、阅读器缩略图栏、列表行都用这一套。
- **侧边栏**：图标改成灰色，只有选中项的图标是强调色；选中底色用浅灰。
- **大标题**：内容区顶部一个 26px 粗体大标题加篇数，工具栏只放工具，去掉重复的标题。
- **继续阅读**：横向铺满一行（4 本），每本显示阅读进度条和批注数。
- **列表**：每行左边加一个小首页缩略图；标签变成灰色小胶囊，紧跟在作者信息后面；默认不选中任何行。
- **状态行**：正在识别、识别失败放进列表顶部的一条紧凑提示里，不再占两整行。
