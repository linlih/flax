# 01 定位与差异化

> 状态：草案 v0.1（2026-11-03）。竞品判断基于初步调研，标注「待核实」的条目需在定稿前逐个确认。

## 1. 一句话定位

**开源、本地优先的论文阅读与知识工具：桌面管理 + iPad 原生精读 + AI，体验做到极致，数据永远属于你。**

## 2. 目标用户（切入人群）

**中文母语、大量阅读英文论文（以 arXiv / AI / CS 为主）的研究生、科研人员和工程师。**

- 论文多、更新快，阅读和整理的痛点最强；
- 同时使用电脑和 iPad，iPad + Apple Pencil 是常见的精读方式；
- 对开源、本地优先、自带 API Key 接受度高；
- 愿意尝鲜，也乐于在社区传播。

暂不服务：重度 Word 引用排版用户（人文社科写长篇论文）、团队协作场景、医学系统综述。

## 3. 我们要解决的问题（来自 Zotero 用户的痛点）

| 痛点 | 根源 | 我们的方案 |
|---|---|---|
| UI 丑 | Mozilla 平台的"数据库三栏"布局，信息密度高 | 以阅读为中心的首页、卡片和列表视图、命令面板，默认极简 |
| 操作杂 | 条目、附件、笔记是父子结构；分类、标签、保存的搜索三套体系并存 | 一篇论文 = 一个实体；组织方式只留文件夹 + 标签 + 智能筛选 |
| 笔记弱 | 笔记是存在数据库里的 HTML 富文本，没有双链 | Markdown + 双链；高亮可拖成引用块并跳回原文；笔记模板 |
| 没有内建 AI | 依赖插件，需要自己配置，大版本更新时容易失效 | 划词、单篇、全库三层 AI，回答带原文定位，支持自带 Key 和本地模型 |
| 没有内建翻译 | 依赖插件，做不了全文对照 | 划词翻译 + 保留排版的全文双语对照 + 术语表 |
| 存储费用高 | 官方文件存储只送 300MB，扩容按年付费 | 自带存储：iCloud、OneDrive、WebDAV、S3、R2 |
| 同步不丝滑 | 数据和文件两条链路，冲突要手动处理，经常报"文件不存在" | 本地优先 + CRDT 自动合并 + 按内容哈希增量同步 |

## 4. 差异点评估

按「竞品是否已有」×「是否容易被抄」×「对目标用户的价值」评估。

| # | 差异点 | 竞品现状 | 可抄性 | 价值 | 结论 |
|---|---|---|---|---|---|
| D1 | **桌面文献库 + iPad 原生精读（Pencil）+ 实时同步，三者合一** | **并非空白**（见 5.1 节）：ReadCube Papers 已有桌面 + iPad + Pencil + AI；小绿鲸有桌面 + iPad + 翻译；Zotero iOS 有手写但功能有限；MarginNote 擅长 iPad 但文献管理弱 | 低：需要原生开发 + 跨平台数据层，工程门槛高 | 高 | **仍是核心差异点，但要靠"做得更好"取胜，而不是"别人没有"** |
| D2 | **用笔圈选文字或图表，直接问 AI 或翻译** | MarginNote 4 在 iPad 上已有 AI 问答和翻译；用笔圈选直接触发 AI 的交互是否存在，**需要实测** | 中 | 高 | **核心交互**，要做成同类最顺手的，而不是唯一的 |
| D3 | **极致的 UI 和交互打磨** | Zotero 和国内工具普遍偏弱；Paperlib 较好（待核实） | 代码可以 fork，但品味和迭代速度很难抄 | 高 | **护城河本体**，但必须靠产品本身证明，不能只是口号 |
| D4 | **开源（AGPL）+ 本地优先 + 开放数据格式 + 自带 Key 和存储** | Zotero 开源但没有 AI；小绿鲸、ReadPaper 闭源、数据在云上；AI 工具都是 SaaS | 中 | 中高（信任、成本、不被锁定） | **重要差异点**，主要针对国内工具和 AI SaaS |
| D5 | 保留排版的全文双语对照 + 术语一致 | 小绿鲸、沉浸式翻译、BabelDOC 已有 | 高 | 高（中文用户刚需） | **基础能力**，必须有，但不构成差异 |
| D6 | 单篇 AI 问答 | 几乎所有 AI 工具都有 | 高 | 中 | **基础能力** |
| D7 | 论文要点（结构化字段）→ 全库可查询的知识表 | Elicit 有，但面向公共论文库；个人文献库方向少见（PaperQA2 待核实） | 中 | 长期高、短期低 | **长期差异点**：第一天顺手积累数据，一个月后体现价值 |
| D8 | 带文献库上下文的阅读（"这个方法你在 A 论文里读过"） | 少见 | 中 | 中高，依赖积累 | **长期差异点**，在 D7 之后 |
| D9 | 丝滑同步 | Zotero 弱；云端产品体验好但不本地 | 中 | 高 | **基础能力**，做不好会直接劝退用户 |

### 评估结论

1. **最强的差异化是 D1 + D2：桌面和 iPad 无缝衔接的精读，加上用笔就能调用 AI。** 工程门槛最高，也最能体现"体验是护城河"。核实后发现单项都有人做过，**真正没有人同时做到的组合是：开源 + 本地优先 + 原生 Pencil + 与笔融合的 AI + 中文双语精读 + 精细打磨**。首个对外版本应围绕这个组合来讲故事。
2. **D3（体验）不是一个功能，而是贯穿所有功能的标准。** 需要用可衡量的指标来约束，见 [05-体验原则](05-体验原则.md)。
3. **D4（开源、本地优先）是信任和传播的基础**，尤其对比小绿鲸、ReadPaper 和各类 AI SaaS。
4. **D5、D6、D9 是基础能力**：没有它们用户不会来，但它们不是用户留下来的理由。
5. **D7、D8 是长期壁垒**：第一版只做"顺手积累"，不作为卖点。

### 风险

- **范围过大**：桌面、iPad、AI、翻译、同步都要做，小团队很容易摊薄。必须严格按 [06-路线图](06-路线图.md) 分阶段推进，每个阶段只把少数几件事做到极致。
- **竞品比预想的更近**：ReadCube Papers 在功能上最接近；小绿鲸抢的是同一批中文用户；Moonlight 是一个迭代很快、已有移动端的 AI 阅读器，并且正在往文献管理扩展。见 5.1 节。
- **体验护城河很难提前验证**：需要尽早做出可交互的原型，找目标用户实测。

## 5. 与主要竞品的对比

| 竞品 | 它们的强项 | 我们的不同 |
|---|---|---|
| Zotero | 管理、引用、生态、开源 | 现代化体验，内建 AI 和翻译，iPad 原生精读，同步顺畅 |
| 小绿鲸 / ReadPaper | 翻译、AI、中文生态、免费 | 开源、本地优先、数据可迁移、iPad 手写、体验打磨 |
| GoodNotes / MarginNote / LiquidText | 手写和非线性阅读 | 有文献库、元数据、AI，数据格式开放，跨平台 |
| SciSpace / NotebookLM / alphaXiv | AI 精读和问答 | 持续积累的个人文献库，本地优先，有手写批注 |
| Elicit | 结构化抽取 | 同样的结构化能力，用在个人文献库上 |

### 5.1 竞品核实结果（2026-11-03，基于网络资料，尚未上手实测）

| 竞品 | 核实到的情况 | 对我们的影响 |
|---|---|---|
| **ReadCube Papers** | 有 iPad 应用，支持 Apple Pencil 阅读、高亮、批注；官方功能对比页列出"和 PDF 对话""和文献库或列表对话"两项 AI 功能，但没写明哪些平台支持；第三方称 AI 会把 PDF 发到 ReadCube 的服务器再交给云端模型，用户评价 AI 跨多篇论文时"还比较初级" | **功能上最接近 D1 的竞品**。我们的不同：开源、本地优先、自带 Key 或本地模型、中文双语精读、用笔调用 AI、打磨程度 |
| **小绿鲸** | 有 iPad 版（没有手机版），平板、网页、电脑三端同步；5 个翻译引擎，整篇翻译保留原格式；术语库、大纲和导图笔记、10 多种笔记模板；文件夹、标签、智能搜索；宣称 275 万用户；**App Store 中国区评分 2.8（420 个评分）**，有用户反映划词翻译用不了、顶栏占空间 | **抢同一批中文用户的直接竞品**。功能覆盖广，但体验口碑差，印证了"体验是护城河"的判断。Pencil 支持程度未知 |
| **MarginNote 4** | 4.4 版（2026 年 5 月）加入沉浸模式；AI 拆书、AI OCR、AI 翻译、AI 问答、AI 生成卡片；Max 档支持自定义模型和 API Key；可以用设备端的 Apple AI；原生支持 Apple Pencil；2026 年 1 月论坛有 iPad 上 AI 功能报错闪退的帖子 | **iPad 上"笔 + AI"最接近 D2 的竞品**。弱点：文献管理和元数据能力弱，学习成本高，数据封闭 |
| **Zotero iOS** | 支持 Pencil 手写，但用户评价"能用，但很有限"：没有压感，颜色少，没有套索；有用户反映某个版本弄丢了"笔写字、手指高亮"的工作方式 | 手写体验有明显短板，是我们的机会 |
| **Moonlight**（韩国 Corca 公司） | 定位"论文的 AI 同事"：解释文字、公式和图表，结合上下文翻译，自动高亮，AI 对话；智能引用卡片、章节预览；有 iOS 和 Android 应用；四档定价（Free / Pro / Premium / Library）；2025 年 3 月宣布要扩展到文献管理、论文搜索、论文推荐 | **迭代快、需要持续关注的 AI 阅读器**。目前不是本地优先，也没有看到 Pencil 深度批注 |
| **ReadPaper** | 云端文献管理（不同来源说的免费额度从 200 篇到 1000 篇不等）；AI 解析、划词和全文对照翻译；Word 插件和 BibTeX；超过 2 亿篇论文的引用图谱；学术社区 | 平台型产品，数据在云上。和我们的本地优先、开源定位区分明显 |
| **Paperlib**（开源） | GPL-3.0，Electron，2.3k star；强项是会议论文（ICLR、NeurIPS 等没有 DOI 的论文）的元数据抓取、智能筛选、RSS 订阅、写作时快速插入引用；LLM 摘要、打标签、语义搜索、对话通过扩展实现；**没有移动端**；最新版本是 2025 年 9 月，作者在 README 中公开招募合作开发者 | 和我们的桌面版定位有重叠，但没有移动端，主要是管理而不是精读，活跃度在下降。**值得借鉴它的会议论文元数据抓取思路**（我们的目标用户也以会议论文为主）。GPL-3.0 与 AGPL-3.0 兼容 |
| **PaperQA2**（开源） | Apache-2.0，9.5k star，持续活跃（最新版本 2026 年 8 月）；面向科研文档、带引用的高准确率 RAG；是 Python 库，不是应用 | **不是竞品，而是候选组件**：可以作为全库问答的后端（以独立进程运行） |
| **Sioyek**（开源） | GPL-3.0，约 1 万 star，代码持续更新，最新正式发布还是 2024 年的 3.0 alpha | 只参考它的阅读交互（引用预览、portal） |

**修正后的竞争格局**

- **D1、D2 都不是空白**，但没有一家能同时做到：开源 + 本地优先、原生 Pencil 精读、和笔融合的 AI、中文双语精读、体验打磨。
- **最危险的三个竞品**：
  1. ReadCube Papers：功能最接近，面向国际用户；
  2. 小绿鲸：用户群相同，覆盖面广，但体验口碑差；
  3. Moonlight：AI 阅读体验好，迭代快，正在往文献管理扩展。
- **我们的机会**：小绿鲸 2.8 分和 Zotero iOS 手写体验有限，说明"功能有但体验差"在这个市场普遍存在。这验证了"体验是护城河"的判断。
