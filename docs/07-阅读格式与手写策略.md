# 07 阅读格式与手写策略

> 状态：草案 v0.1（2026-11-04）。

## 1. 决策

| 事项 | 决定 |
|---|---|
| 第一版的阅读格式 | **只支持 PDF**：排版是作者定稿的样子，最美观，所有论文都有，手写批注也最好做 |
| HTML 阅读模式 | **第三阶段再做**，和手机版一起上线（手机屏幕窄，最需要重排） |
| 为 HTML 预留 | 从第一天起，批注就用"原文 + 前后文"定位，数据模型支持一篇论文有多个版本，以后加 HTML 不用推倒重来 |
| HTML 模式下的手写 | 不在文字上方自由手写；用"手写转文字 + 笔势转批注 + 锚定手写便签"代替（见第 4 节） |

## 2. 为什么第一版只做 PDF

1. **排版最好**：PDF 是作者定稿的版式，公式、图表、双栏排版都和发表时一致；HTML 是自动转换的，质量参差不齐。
2. **覆盖面最全**：所有论文都有 PDF；arXiv 的 HTML 只覆盖用 TeX 投稿的较新论文，部分会转换失败。OpenReview 会议论文和期刊论文大多只有 PDF。
3. **手写最自然**：版式固定，笔迹按页面坐标存储，不会错位。iPad Pencil 批注是必须项，PDF 是最稳的基础。
4. **聚焦**：第一版集中把 PDF 阅读器打磨到极致，符合"体验是护城河"的策略。

## 3. PDF 与 HTML 的对比（供以后参考）

| | PDF | HTML（arXiv 官方，或从 PDF 解析生成） |
|---|---|---|
| 覆盖面 | 所有论文 | 只有部分 arXiv 论文；arXiv 至今仍标为实验性功能 |
| 排版 | 固定，和作者看到的一致，页码准确 | 自动重排，手机和平板竖屏阅读更舒服 |
| 翻译 | 要先从 PDF 提取文字，双栏、公式、表格容易出错 | 结构清晰，翻译和对照质量更高 |
| AI | 需要先解析 | 结构化文本，定位到段落和公式更准确 |
| 引用跳转 | 靠解析识别 | 引用本身就是链接 |
| Pencil 手写 | 适合 | 重排后笔迹会错位，不能按坐标存储 |

**一个不影响第一版范围的优化**：即使只用 PDF 阅读，翻译和 AI 也可以在后台优先使用 arXiv 的 HTML 结构化文本（如果有的话），提高质量。是否在第一版做，实现时再评估。

## 4. HTML 模式下的手写方案（第三阶段起）

难点：HTML 会随屏幕宽度和字号重新排版，按坐标贴在文字上方的笔迹会错位。思路是**让手写不依赖固定坐标**。

| 方案 | 做法 | 参考 | 用在哪里 |
|---|---|---|---|
| **A. 手写转文字** | 批注框、标签、笔记、AI 提问框都可以直接用笔写，系统自动识别成文字 | iPadOS 自带的 Scribble | **所有模式**，第二阶段 iPad 版就做 |
| **B. 笔势转结构化批注** | 划过一行 → 高亮或下划线；段落旁画竖线 → 标记整段；圈一下 → 选中并弹出 AI 菜单；画问号 → 打上"疑问"标签。识别后存成普通文本批注，能随排版移动 | GoodNotes 的形状吸附；可重排文档中笔迹随文字移动的相关研究 | PDF 模式里也有用（划过文字自动吸附成高亮）；HTML 模式下是用笔的主要方式 |
| **C. 锚定手写便签** | 手写内容放在一个独立的小画布里，挂在某段文字上（页边或段落之间）。排版变化时便签跟着这段文字走，里面的笔迹不变形 | 据了解，Kindle Scribe 的 Active Canvas 采用类似思路（未核实） | HTML 模式；在 PDF 模式里显示在对应段落的页边 |
| **D. PDF 笔迹在 HTML 中显示为标记** | PDF 上的自由笔迹，在 HTML 模式里显示为段落旁的小标记，点击可预览，或切回 PDF 查看 | 多数阅读器的做法 | 兜底，保证跨模式不丢信息 |
| **E. 手写识别做索引** | 用设备端的手写识别（如 Apple Vision 框架）把笔迹转成文字，只用于搜索和 AI，不替换原笔迹 | 笔记类应用的常见做法 | 所有模式；中文识别准确率需要实测 |

### 跨模式的显示规则

| 批注 | 在 PDF 模式 | 在 HTML 模式 |
|---|---|---|
| 文本高亮、下划线（包括笔势转换来的） | 正常显示 | 正常显示（通过"原文 + 前后文"重新定位） |
| 文字批注、标签 | 正常显示 | 正常显示 |
| PDF 上的自由笔迹 | 正常显示 | 段落旁的标记，点击预览（D） |
| 锚定手写便签 | 显示在对应段落的页边 | 页边或段落之间（C） |
| 区域选择（图表、公式） | 正常显示 | 定位到对应的图、表或公式元素；找不到时显示为标记 |

## 5. 分阶段

| 阶段 | 阅读格式 | 手写 |
|---|---|---|
| 第一阶段（桌面） | 只支持 PDF | 不涉及（桌面没有 Pencil） |
| 第二阶段（iPad） | 只支持 PDF | PDF 自由手写；A：所有文本框支持 Scribble；B：笔划过文字吸附成高亮、圈选问 AI |
| 第三阶段（知识层 + 手机） | 加入 HTML 阅读模式：优先使用 arXiv 官方 HTML，没有时从 PDF 解析生成；手机默认 HTML | B 扩展到 HTML 模式；D：PDF 笔迹显示为标记 |
| 第四阶段 | — | C：锚定手写便签；E：手写识别做索引 |

## 6. 需要注意的

- **一键回退**：HTML 显示有问题时，提供"切回 PDF"按钮。
- **版本对应**：arXiv 论文有 v1、v2 等版本，HTML 和 PDF 必须对应同一版本，否则批注会对不上。
- **版权**：HTML 和 PDF 一样，沿用论文本身的许可证；本地缓存只供个人阅读，不提供公开分发。
- **解析工具**：没有官方 HTML 时，可以用 Docling、MinerU、GROBID 等工具从 PDF 生成结构化文本，集成前逐个确认许可证。
