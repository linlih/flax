# 04 数据模型

> 状态：草案 v0.1（2026-11-03）。这是跨平台的契约，一旦发布就要保持向后兼容，修改需要版本号和迁移方案。

## 1. 原则

1. **一篇论文 = 一个实体**：PDF、元数据、批注、笔记、卡片都挂在它下面，不向用户暴露"附件"的概念。
2. **开放格式**：所有用户数据都能导出成通用格式（Markdown、JSON、BibTeX、标准 PDF 批注），不依赖任何私有格式。
3. **不修改原始 PDF**：批注单独存储；需要时再导出带批注的 PDF 副本。
4. **跨渲染器、跨版本稳定**：同一条批注在 PDF.js（桌面）和 PDFKit（iPad）上必须显示在相同的位置；以后加入 HTML 阅读模式时，文本类批注也要能重新定位（见 [07-阅读格式与手写策略](07-阅读格式与手写策略.md)）。
5. **所有 ID 用 UUID**，在各设备上离线生成，不冲突。

| 字段 | 说明 |
|---|---|

### Annotation（批注）

```jsonc
{
  "id": "uuid",
  "paperId": "uuid",
  "fileHash": "sha256…",          // 绑定到具体文件，避免预印本和正式版混淆
  "type": "highlight" | "underline" | "note" | "ink" | "area" | "ink_note",
  "origin": "select" | "gesture" | "ai",   // 怎么创建的：选中文字、笔势转换、AI 生成
  "color": "#FFD400",
  "semantic": "method" | "result" | "question" | "important" | null,  // 颜色的语义，可自定义
  "page": 3,                       // 从 0 开始
  "target": { ... },              // 定位方式，见下
  "comment": "markdown 文本",
  "createdAt": "...", "updatedAt": "...", "device": "ipad-xxx"
}
```

**文本高亮的定位（双保险）**：

```jsonc
"target": {
  "rects": [[x0, y0, x1, y1], ...],     // PDF 页面坐标（单位 pt，原点在左下角），不随缩放变化
  "quote": { "exact": "选中的原文", "prefix": "前 32 个字符", "suffix": "后 32 个字符" }
}
```
- 优先用 `rects` 显示；
- 如果不同渲染器的文本层对不上，用 `quote` 重新在页面里查找定位（参考 W3C Web Annotation 的 TextQuoteSelector）。

**手写笔迹（ink）**：

```jsonc
"target": {
  "strokes": [
    {
      "tool": "pen" | "pencil" | "marker",
      "color": "#1E1E1E",
      "width": 1.6,                    // pt
      "points": [[x, y, pressure, t], ...]   // PDF 页面坐标；pressure 在 0–1 之间；t 是相对毫秒
    }
  ],
  "bbox": [x0, y0, x1, y1]
}
```
- iPad 上使用 PencilKit 录制，保存时**转换为上面的开放格式**；PKDrawing 原始数据最多只作为本地缓存，不作为同步的权威数据；
- 桌面端在 PDF.js 页面上叠一层 SVG 或 Canvas 来渲染；
- 导出时转换成标准 PDF 的 Ink 批注。

**区域选择（area）**：`target.rect` + 可选的截图缓存，用于图表和公式（可以直接拿去问 AI）。

**笔势转换的批注**：笔划过文字、在段落旁画竖线等笔势，识别后存成普通的 `highlight` 或 `underline`，`origin` 记为 `gesture`，不保存原始笔迹。这样它们在 PDF 和 HTML 两种模式下都能显示。

**锚定手写便签（ink_note，第四阶段）**：用于 HTML 模式下的自由手写，挂在一段文字上，而不是页面坐标上。

```jsonc
"target": {
  "anchor": {
    "quote": { "exact": "…", "prefix": "…", "suffix": "…" },   // 挂在哪段文字上
    "blockId": "sec3.2-p2"                                   // 可选：段落、图、公式的 ID
  },
  "canvas": { "w": 320, "h": 180 },          // 便签自己的画布尺寸
  "strokes": [ /* 格式同 ink，坐标是便签画布内的坐标 */ ],
  "placement": "margin" | "inline"           // 显示在页边，或插在段落之间
}
```
在 PDF 模式中，锚定手写便签显示在对应段落的页边。

**跨模式显示规则**：
- 文本类批注（highlight、underline、note）通过 `quote` 在 PDF 和 HTML 之间重新定位；
- PDF 上的自由笔迹（ink）不在 HTML 中直接绘制，而是显示为段落旁的标记；
- 完整规则见 [07-阅读格式与手写策略](07-阅读格式与手写策略.md)。

### KeyPoints（论文要点）
阅读器里的"要点"标签。上半部分是**导读**（读之前看：这篇讲什么、怎么读），下半部分是**结构化要点**（读完后核对：每篇字段相同，汇总成全库可查询的表）。

```jsonc
{
  // 导读
  "oneLiner": "不用循环和卷积，只靠注意力做翻译：效果更好，训练也快得多。",
  "readingGuide": {
    "estimatedMinutes": 25,
    "steps": [
      {
        "title": "先看图 1 和 3.2 节",
        "why": "整个模型和多头注意力都在这里，是全文核心",
        "kind": "core" | "evidence" | "skim" | "skip",   // 精读 / 看依据 / 略读 / 可跳过
        "targets": ["fig:1", "sec:3.2"],                 // 段落、图、表、章节的 ID
        "pages": [2, 3]                                  // 从 0 开始，用于跳转和显示"第 3–4 页"
      }
    ]
  },

  // 结构化要点
  "problem": "要解决的问题",
  "method": "方法",
  "datasets": ["..."],
  "metrics": [{"name": "...", "value": "..."}],
  "findings": ["主要结论"],
  "limitations": ["局限"],
  "myTakeaway": "我的想法",

  // 来源和确认
  "source": "ai" | "user" | "mixed",     // 是 AI 生成，还是用户确认或修改过
  "confirmedAt": "时间戳" | null,         // null = 还没确认，界面显示"由 AI 生成，还没确认"
  "evidence": { "method": ["annotation:uuid", "para:p3-2"], "oneLiner": ["para:p1-1"] },   // 每个字段的原文依据
  "model": "生成时用的模型和版本",
  "generatedAt": "时间戳"
}
```
- **导读不保存阅读进度**："在读 · 第 4 页"由当前阅读位置和 `steps[].pages` 实时算出，不写进数据，避免多台设备互相覆盖；
- **重新生成**只替换用户没改过的字段（逐字段比较 `source`），用户改过或确认过的字段保留；
- `oneLiner` 也用在文献库列表和"继续阅读"卡片上，代替摘要的第一句；
- `readingGuide` 只是建议，不参与全库查询；全库对比表只用结构化要点的字段。

### Term（术语）
全库共用的术语，也是一个"概念页"。翻译、查词、生词注释都按它的译法来，保证一个词在全库只有一种译法。

```jsonc
{
  "id": "uuid",
  "term": "query",                       // 主词条（英文原形）
  "aliases": ["queries", "Q", "query vector"],   // 复数、缩写、别名，都匹配到这个术语
  "translation": "查询向量",
  "locked": true,                        // 锁定后，翻译引擎必须用这个译法
  "status": "pending" | "confirmed",     // AI 提取的新术语先是 pending，用户确认后才参与翻译
  "definition": "注意力里负责"提问"的向量……",
  "definitionSource": "ai" | "user" | "mixed",
  "occurrences": [                       // 出现在哪些论文里
    {
      "paperId": "uuid",
      "role": "defines" | "core" | "extends" | "uses",   // 首次定义 / 核心方法 / 在此基础上改进 / 沿用
      "summary": "提出 Q、K、V 的写法……",                 // 这篇论文里它是怎么用的
      "anchors": ["para:p3-2"], "pages": [3]
    }
  ],
  "related": ["term:uuid"],              // 相关术语
  "createdAt": "...", "updatedAt": "..."
}
```
- **从哪来**：生成论文要点时，AI 顺便提取这篇论文的术语和它在文中的角色；已有的术语只追加 `occurrences`，新术语记为 `pending`；
- **不存在 Term 里、而是实时查出来的**：提到这个术语的批注（用 `aliases` 在批注原文里匹配）、链接到它的笔记（笔记里的 `[[查询向量]]`）。这样批注和笔记改了，概念页自动更新；
- **和生词本分开**：生词本（VocabEntry：单词、原句、出处、复习记录）是个人学英语用的；查词卡上收藏一个词时，系统判断它是术语就进术语，否则进生词本；
- 导出：术语表可以导出为 CSV 或 Markdown，也可以导入别人整理好的术语表（例如某个领域的标准译法）。

### 其他
- **TranslationCache**：`fileHash + 段落 ID + 目标语言 + 引擎 → 译文`，只在本地，可以重新生成；
- **Term（术语）**：见上面的"Term（术语）"一节，需要同步；
- **AIConversation**：对话记录，引用的原文位置也要保存；
- **Subscription**：arXiv 分类或关键词订阅（第三阶段）。

## 3. 同步范围

| 同步 | 不同步（可以本地重建） |
|---|---|
| Paper、Folder、Annotation、Note、KeyPoints、Term、VocabEntry、AIConversation、PDF 文件 | 全文索引、向量索引、翻译缓存、缩略图、文件的本地状态 |

## 4. 导出格式

| 数据 | 格式 |
|---|---|
| 文献元数据 | BibTeX、RIS、CSL-JSON |
| 笔记 | Markdown（每篇一个 `.md`，带 YAML 头信息） |
| 批注 | JSON（完整数据）；嵌入批注的 PDF 副本；Markdown 摘录 |
| 整个文献库 | 一个目录：`papers.json` + `notes/*.md` + `files/<hash>.pdf` |

## 5. 导入

- PDF 文件或文件夹（自动识别元数据）
- BibTeX、RIS、CSL-JSON
- Zotero 文献库：读取用户本地的数据库和 storage 目录，作为迁移入口。这只是读用户自己的数据，不使用 Zotero 的代码，也不依赖 Zotero 运行
