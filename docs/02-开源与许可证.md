# 02 开源与许可证

> 状态：草案 v0.1（2026-11-03）。不构成法律意见，正式发布前请律师审核。

## 1. 决策

| 事项 | 决定 |
|---|---|
| 项目许可证 | **AGPL-3.0** |
| 贡献协议 | **CLA**（贡献者授权项目方重新授权），保留以后做双许可证或商业版的可能 |
| 品牌 | 注册商标：fork 可以存在，但不能使用本项目的名称和 Logo |
| 是否依赖 Zotero | **不依赖**。不运行 Zotero，也不把它当数据后端 |

### 为什么选 AGPL
- 任何人修改后再发布，或做成网络服务，都必须开源，闭源抄袭不划算；
- 目标用户是个人研究者，AGPL 对他们没有使用限制；
- 可以合法使用一批成熟的 AGPL 组件，节省大量开发时间（见下文）。

### 为什么要 CLA + 商标
- 开源以后代码可以被 fork，**真正防抄袭的是商标和品牌**，而不是代码；
- 有了 CLA，以后才能为托管服务或企业版提供不同的授权。

## 4. 其他法律风险与对策

| 风险 | 对策 |
|---|---|
| PDF 版权 | 只管理用户自己的文件；不做公共 PDF 分享或文献库共享；不接入盗版来源 |
| 翻译版权 | 译文只供个人阅读使用，不提供公开分享译文的功能 |
| 元数据来源的条款 | Crossref、OpenAlex、Semantic Scholar、arXiv 各有使用条款和频率限制，商用前逐个确认 |
| 网页抓取 | 只在用户浏览器里、用户本来就有权限访问的页面上抓取；不在服务端批量爬出版商网站 |
| AI 隐私 | 发送论文内容给模型服务商之前明确告知用户；提供本地模型选项 |
| 个人信息 | 如果做账号和托管同步，要遵守个人信息保护法、GDPR 等法规 |
| 生成式 AI 监管（中国） | 面向公众提供托管的 AI 服务可能需要备案；用户自带 Key 或使用本地模型时风险较低 |
| 商标 | 宣传中只说"支持导入 Zotero 文献库"，不使用 Zotero 的 Logo，不暗示官方合作 |

## 5. 工程上的保障

- [ ] 在 CI 中加入依赖许可证扫描，发现不兼容的许可证就让构建失败；
- [ ] 维护 `THIRD_PARTY_NOTICES` 文件，列出所有第三方组件及其许可证；
- [ ] 在"关于"页面注明 CSL 项目并附 citationstyles.org 链接；
- [ ] 准备 CLA 文本，接入 CLA 签署机器人。

## 6. 可持续性（预留，第一版不做）

- 核心功能永久免费，本地使用完全不受限；
- 可选的收费服务：官方托管的同步和存储、给没有 API Key 的用户提供 AI 额度、团队版；
- 参考：Logseq、AppFlowy 等采用"AGPL + 托管服务"模式的项目。
