# 05 体验原则

> 状态：草案 v0.1（2026-11-03）。体验是这个项目的护城河，本文档里的指标是硬性要求，不是建议。

## 1. 核心原则

1. **阅读优先**：打开应用，第一眼看到的是"正在读"和"待读"，而不是一张数据库表格。
2. **零配置**：拖入 PDF 就能开始读；不弹设置向导，不弹对话框；高级功能按需出现。
3. **一次只做一件事**：每个界面只有一个主要任务，次要信息折叠起来。
4. **手感一致**：桌面和 iPad 上的同一个动作，有一致的反馈和结果。
5. **永远可撤销**：所有操作都能撤销，删除默认进回收站。
6. **快就是好看**：任何卡顿都是体验缺陷，按严重 bug 处理。

## 2. 性能预算（硬指标）

| 场景 | 目标 |
|---|---|
| 冷启动到可交互 | ≤ 1 秒（桌面）/ ≤ 1.5 秒（iPad） |
| 打开一篇 PDF 到第一页显示 | ≤ 300ms |
| 滚动、缩放 | 稳定 60fps（ProMotion 设备 120fps） |
| Pencil 落笔到墨迹显示 | 跟系统备忘录手感一致（用 PencilKit 保证） |
| 1 万篇规模的文献库中搜索 | ≤ 100ms |
| 拖入 PDF 到元数据识别完成 | ≤ 3 秒（网络正常时） |
| 划词翻译出结果 | ≤ 1 秒开始显示（流式输出） |

每个版本发布前跑性能测试，不达标就不发布。

## 3. 交互规范

### 通用
- **Cmd+K 命令面板**：所有操作都能从这里找到；
- 键盘优先但不强迫：常用操作都有快捷键，鼠标和触控同样顺手；
- 右键菜单不超过一层；
- 加载、同步、AI 生成都要有明确但不打扰的状态提示。

### 阅读器
- 引用标记（如 [23]）悬停预览参考文献，并显示"已在库 / 一键入库"；
- 图、表、公式的引用悬停预览；
- 阅读位置在各设备之间同步，换设备接着读；
- 双语对照可以一键切换：原文、译文、对照三种模式。

### iPad + Pencil
- 防误触、双指缩放和翻页做到"感觉不到"；
- **用笔圈选一段文字或一张图 → 弹出"问 AI / 翻译 / 高亮 / 摘到笔记"**；
- 用笔划过文字时自动吸附成文本高亮（可以关闭）；
- 用套索把批注拖进笔记，生成引用块，可以跳回原文；
- 支持 Scribble：在搜索框和笔记里手写自动转文字。

### 笔记
- 阅读和笔记左右分栏，宽度可以拖动调整；
- 高亮拖进笔记 = 引用块，点击跳回原文位置；
- 新建笔记时提供模板（问题 / 方法 / 结论 / 局限 / 我的想法），AI 可以预填。

## 4. 视觉规范

- 先建立设计 token（颜色、字体、字号、间距、圆角、阴影、动效时长），桌面和移动端共用；
- **中英混排单独调校**：字体组合、行高、标点挤压；
- 深色模式从第一天就支持，而不是后补；
- 动效用于说明"发生了什么"（例如高亮飞进笔记），不做装饰性动画。

## 5. 参考产品

| 产品 | 参考什么 |
|---|---|
| Linear | 速度、键盘操作、命令面板、视觉克制 |
| Things | 简洁、零学习成本 |
| Readwise Reader | 高亮和回顾的流程 |
| Heptabase | 卡片与白板组织知识 |
| GoodNotes / Notability | Pencil 手感 |
| Highlights / Sioyek | 论文阅读细节（引用预览、导出） |
| Raycast | 命令面板交互 |

## 6. 工作流程

1. **先设计后编码**：核心界面先出高保真可交互原型，用户试用后再实现；
2. **自己每天用**：团队成员日常用它读论文；
3. **每周修小毛病**：固定时间集中处理体验上的小问题；
4. **用户实测**：每个阶段结束时，找 5 位以上目标用户做可用性测试，记录问题；
5. **体验评审**：新功能合并前，要过一次体验检查清单（性能、空状态、错误状态、深色模式、键盘操作、撤销）。
